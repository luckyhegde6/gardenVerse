## ⚠️ Critical: Process Management on Windows (Non-Blocking)

### The Golden Rule
**NEVER** run long-lived processes (Gradle, emulator) directly in this agent's bash session. They will **block the agent permanently** and prevent iteration.

### Windows Process Launch Cheat Sheet

| Command | Behavior | Use Case |
|---------|----------|----------|
| `start "Title" cmd /c "command"` | ✅ New window, **non-blocking** | Gradle build, emulator |
| `start /B "" command` | ❌ Same console, **still blocks** | NEVER use for long-lived processes |
| `command` | ❌ Blocks until done | Only for quick commands (< 10s) |

### How to Build APK (Non-Blocking)

```batch
:: ✅ CORRECT — Opens new window, agent continues
start "APKBuild" cmd /c "cd /d F:\...\mobile\android && set JAVA_HOME=C:\jdk17\jdk-17.0.12 && set ANDROID_HOME=C:\Users\lucky\AppData\Local\Android\Sdk && gradlew.bat assembleDebug -x :expo-updates:kaptDebugKotlin --no-daemon && echo BUILD_DONE > F:\...\apk_build_done.flag"

:: ❌ WRONG — Blocks agent for 5-10 minutes!
gradlew.bat assembleDebug
```

### How to Launch Emulator (Non-Blocking)

```batch
:: ✅ CORRECT — Opens new window, agent continues
start "Emulator" cmd /c "C:\...\emulator -avd Pixel_7_API_34 -no-snapshot"

:: ❌ WRONG — Blocks agent permanently!
emulator -avd Pixel_7_API_34
```

### Polling Pattern (Run in Main Session — Non-Blocking)
After starting builds in separate windows, poll for completion:

```bash
:: Wait for Gradle build (flag file)
for /l %i in (1,1,120) do (if exist F:\...\apk_build_done.flag echo BUILD_COMPLETE! & exit /b) & timeout /t 5 /nobreak >nul

:: Wait for emulator boot
adb shell getprop sys.boot_completed 2>&1 | findstr "1"

:: Check APK exists
dir F:\...\arm64-v8a-debug.apk
```

### Summary
- Gradle build → `start "Title" cmd /c "batch_script"` + poll flag file
- Emulator → `start "Title" cmd /c "emulator ..."` + poll `adb shell getprop`
- APK install + testing → run directly (quick commands)
- Never use `start /B` for builds
- Use `adb install`, `adb shell`, `adb logcat` directly (non-blocking, finishes quickly)

## Troubleshooting

### Gradle Timeout on First Run
First Gradle build downloads ~500MB of dependencies. Run with 20+ minute timeout.
If it fails, retry — Gradle caches downloads and subsequent runs are fast.

### JAVA_HOME Not Found
```batch
@echo off
set "JAVA_HOME=C:\jdk17\jdk-17.0.12"
set "PATH=%JAVA_HOME%\bin;%PATH%"
java -version
```
PowerShell's `set` doesn't work for cmd — use batch scripts for build commands.

### Stale Java Processes
```batch
taskkill /F /IM java.exe
```
Gradle daemon locks files. Kill all java.exe before re-running build.

### expo prebuild Fails
Delete `android/` folder first, then re-run:
```batch
rmdir /s /q packages\mobile\android
npx expo prebuild --platform android --clean
```

### Build Tools Version Mismatch
Check installed versions:
```bash
C:\Users\lucky\AppData\Local\Android\Sdk\cmdline-tools\latest\sdkmanager.bat --list_installed
```
Install missing: `sdkmanager "build-tools;36.1.0" "platforms;android-36.1"`

### APK Install Fails
Ensure emulator is running and ADB is connected:
```bash
adb devices
adb install -r packages/mobile/android/app/build/outputs/apk/debug/app-debug.apk
```
